# ForteHire — Recruitment Intelligence & Workflow Optimisation Platform

**Live Demo:** `https://fortehire.onrender.com` · **Product Docs:** `/docs` · **BI Workbook:** `ForteHire_Analytics.pbix`

ForteHire is a recruiting action-queue and pipeline analytics platform built for agency and in-house recruiters managing high-volume pipelines. Rather than burying urgent follow-ups inside flat task lists, ForteHire ranks every open workflow action using a deterministic, auditable priority score and explains *why* each item needs attention right now.

> **Product Guardrail:** ForteHire prioritises **workflow actions**, not people. There is **no AI** and **no candidate scoring** anywhere in the system.

---

## Problem & Hypothesis

Recruiters rarely drop candidates because they lack data—they drop them because standard ATS/CRM task views treat an overdue hiring-manager follow-up the same as a routine check-in due next week.

- **Hypothesis:** Surfacing a single, live-ranked Action Queue with explicit urgency reasons reduces triage friction and prevents high-priority hiring bottlenecks from going stale.
- **North Star Metrics (tracked live in `/analytics`):**
  1. Time to identify the next action
  2. Overdue action rate
  3. Percentage of tasks completed within due date

## Deterministic Priority Engine (`priority.py`)

Implemented as a pure, stateless Python function (`score_action()`) with zero database access so it can be unit-tested cleanly and recomputed live on every read as dates advance.

| Factor | Scoring Rule | Max Points |
|---|---|---|
| **Due Date (D)** | Overdue >3d (`+15`), Overdue 1–3d (`+12`), Due today (`+9`), Due tomorrow (`+6`) | 15 |
| **Waiting Time (W)** | ≥5 days since last activity (`+10`), 3–4 days (`+6`), <3 days (`0`) | 10 |
| **Job Priority (J)** | High / Critical (`+10`), Normal (`+5`), Low (`0`) | 10 |
| **Blocker (B)** | Hiring-manager feedback = `Pending` (`+10`) | 10 |

- **Priority Bands:** **High** (`32–45`) · **Medium** (`18–31`) · **Low** (`0–17`)
- **Explainability:** Each task renders a plain-English breakdown (e.g., `+15 5 days overdue, +10 Waiting 5 days, +10 High priority job, +10 Feedback pending`).

## Architecture & Tech Stack

- **Backend:** Python, Flask, SQLite (6 normalized tables with `FOREIGN KEY` and `CHECK` constraints)
- **Analytics & BI:** pandas (live metrics + CSV export), Chart.js (dashboard charts), Power BI Desktop (`ForteHire_Analytics.pbix`)
- **Frontend:** Jinja2 templates, semantic Flexbox/Grid CSS, vanilla JavaScript (`fetch()` mutations)
- **Testing:** `pytest` unit test suite for `priority.py` (`test_priority.py`)

### Live Analytics vs. Power BI Snapshot

ForteHire separates operational reporting from executive BI:

- **Flask Analytics (`/analytics`):** Queries SQLite live on every request and recalculates priority scores against the current date. Completing or snoozing an action updates KPIs immediately.
- **Power BI Dashboard (`ForteHire_Analytics.pbix`):** Reads a static CSV snapshot exported via `python export_powerbi.py` into `data/`. To reflect new mutations in Power BI, re-run the export script and click **Refresh** in Power BI Desktop.

*Note: All recruiters, jobs, candidates, and actions in this project are synthetic demo data generated by `seed_data.py`.*

## Local Setup

```bash
# 1. Clone and install dependencies
git clone https://github.com/<your-username>/ForteHire.git
cd ForteHire
pip install -r requirements.txt

# 2. Run Priority Engine unit tests
pytest -v

# 3. Initialize SQLite schema and seed synthetic data
python seed_data.py

# 4. Run the Flask server
python app.py
# Visit http://127.0.0.1:5000

# 5. (Optional) Export CSVs for Power BI Desktop
python export_powerbi.py
```
